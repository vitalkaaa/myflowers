# my-flowers — дневник растений

FastAPI + SQLite + Jinja2. Напоминания об уходе отправляются в Telegram.

## Запуск

```bash
cp env.example .env        # заполнить APP_PASSWORD, SECRET_KEY, TELEGRAM_*
docker compose up -d --build
```

На Linux-сервере папку для базы нужно создать заранее и отдать пользователю контейнера
(uid 1000) — иначе Docker создаст её от root и приложение не сможет записать базу
(`unable to open database file`):

```bash
mkdir -p data && sudo chown -R 1000:1000 data
```

Сайт откроется на http://localhost:8080 (порт меняется в `WEB_PORT`). При первом запуске база (`data/flowers.db`)
заполняется начальным списком растений и фото из `seed_photos/`.

Проверить Telegram: тестовое сообщение с кнопкой (уходит всегда) и рассылка на сегодня
(уходит, только если есть дела):

```bash
docker compose run --rm --no-deps reminders python -m app.notifier --test
docker compose run --rm --no-deps reminders python -m app.notifier --now
```

Посмотреть, как будет выглядеть рассылка в день ухода — на ближайший день с делами
или на указанную дату. Сообщения помечены «🧪 Пример», кнопки в них в историю не пишут:

```bash
docker compose run --rm --no-deps reminders python -m app.notifier --preview
docker compose run --rm --no-deps reminders python -m app.notifier --preview 2026-11-02
```

### Кнопки в Telegram

Напоминания приходят по сообщению на каждое действие (💧 полив, 🌱 подкормка…). В тексте — сводка
(«Осталось 21 из 23 · всего ≈ 2,6 л»), растения — кнопками по одной в ряд с объёмом полива,
по комнатам (поле «Где стоит»); просроченные помечены «⚠️ +3 дн.». Ниже — «✅ Всё полито»
и «⏰ +1 день / +2 дня». Нажатие на растение записывает событие в историю — как кнопка на сайте,
повторное нажатие на «✅» снимает отметку, на «⏰» — возвращает растение в список. Повторная отметка того же действия в тот же день (на сайте или в боте)
второго события не создаёт. «⏰» откладывает напоминание для всех ещё не отмеченных растений
сообщения (почва ещё влажная) — до отметки «сделано» или до выбранного дня.

Вечером (`REMINDER_REPEAT_CRON`, по умолчанию 21:30) приходит повтор «🔁 Ещё не отмечено» —
только то, что так и не отметили; пустое значение отключает повтор. Команда `/today` в чате
напоминаний присылает дела на сегодня.
Нажатия принимает контейнер `reminders` (long polling, наружу ничего открывать не нужно),
поэтому он должен быть запущен: `docker compose up -d`.

Кнопки срабатывают только в чате из `TELEGRAM_CHAT_ID`. В личке с ботом их видите только вы;
если указать канал, отмечать полив сможет любой, кто может нажимать кнопки в этом канале.
Свой chat ID бот пришлёт в ответ на `/start`.

## Доступ из интернета

По умолчанию сайт слушает только 127.0.0.1. На сервере в `.env`:

```
WEB_BIND=0.0.0.0
WEB_PORT=80
APP_PASSWORD=<длинный случайный пароль>
```

Затем `docker compose up -d --force-recreate` — сайт откроется на `http://<IP сервера>`
(порт 80 должен быть открыт в security group). Без HTTPS пароль и cookie передаются
открытым текстом — для постоянного использования лучше домен и HTTPS.

### Обновление сервера

С вашего компьютера, из папки проекта (нужен доступ по ssh):

```bash
sh deploy.sh
```

Скрипт прогоняет тесты, копирует код без `.env` и `data/` и пересобирает контейнеры.
Адрес и папка задаются переменными `DEPLOY_HOST` и `DEPLOY_DIR`. Docker на сервере
вызывается через `sudo` (спросит пароль, если нужен); без sudo — `DEPLOY_DOCKER=docker sh deploy.sh`.

## Резервные копии

Контейнер `reminders` каждую ночь (`BACKUP_CRON`, по умолчанию 03:30) сохраняет копию
БД вместе с фото в `data/backups/` и хранит последние `BACKUP_KEEP` (14) штук.
Копия вручную: `docker compose run --rm web python -m app.backup`.

Копии лежат на том же диске, что и база, — время от времени забирайте их к себе:

```bash
scp 'user1@95.174.94.151:/home/user1/myflowers/data/backups/*' ./backups/
```

Восстановление: остановить контейнеры, положить копию на место `data/flowers.db`
(и удалить `data/flowers.db-wal`, `data/flowers.db-shm`), запустить снова.

## Что умеет

- Блок «Сегодня» на главной: дела по действиям, у каждого растения галочка и «⏰ +1 д. / +2»
  (отложить), внизу «✅ Всё полито». Отметки уходят без перезагрузки страницы — прокрутка
  и поиск сохраняются, во всплывашке «Отмечено · Отменить».
- Список растений карточками с фото и ближайшим делом или таблицей (переключатель; в таблице
  сортировка по одному или нескольким полям: клик по заголовку, Shift+клик добавляет поле).
  Поиск по названию, виду и месту, фильтры «по месту», «нужно сегодня», «ядовитые».
- Карточка растения: параметры ухода, галерея фото (хранятся в БД) с просмотром поверх
  страницы и лентой роста, дневник (фото к записи, правка записей), история ухода.
  У каждой задачи одна кнопка «✓», в меню «⋯» — «сделал(а) раньше» и «отложить».
  Если по истории поливов вы поливаете заметно чаще или реже, чем указано в карточке,
  появится подсказка обновить интервал.
- Новое растение можно сразу добавить с фото и заполнить по справочнику видов (полив, условия,
  факты, болезни, пересадка), всё остаётся редактируемым. Ошибка в форме показывается над формой,
  введённое не теряется.
- Архив вместо удаления: погибшие и подаренные растения пропадают из списка и напоминаний,
  фото, дневник и история сохраняются (`/archive`). Удалить навсегда можно только из архива.
- Напоминания: 💧 полив (интервалы для сезона роста и покоя), 🌱 подкормка (сезон роста),
  🪴 пересадка (март–апрель), 💦 опрыскивание (отопительный сезон), 🧽 протирка листьев.
  Следующий срок считается от последней отметки «сделано» (или от дня «отложить»).
- Сезоны (`SEASONS` в `app/care.py`): рост апр–сен, отопление окт–апр. Интервал и объём
  полива между сезонами меняются плавно за месяц, а не скачком 1 апреля / 1 октября.
- Календарь (`/calendar`): месяц с отметками «сделано» и прогнозом ухода по интервалам,
  по клику на день — список дел с объёмом полива, кнопками «✓» и «⏰»; просроченное можно
  отметить исходной датой, за прошедший день — отметить любое действие.
- История (`/history`): все отметки по всем растениям с фильтром по растению и действию.
- Примерный объём полива (в сезон роста; в покое — вдвое меньше), справочные факты, рекомендации
  по пересадке (грунт, горшок, дренаж) и «Частые болезни и вредители» в карточке растения.
- Тёмная тема: кнопка 🌙/☀️ в шапке, без выбора — по настройке системы; видимый фокус для работы с клавиатуры, PWA:
  сайт можно добавить на главный экран телефона (данные не кэшируются на устройстве).

## Дамп в JSON

Все растения с комментариями и историей ухода (без фото):

```bash
docker compose run --rm web python -m app.dump -o data/dump.json
docker compose run --rm web python -m app.dump --unprocessed   # только необработанные комментарии, в stdout
# выгрузить новые записи и пометить их обработанными (пометка — только после успешной записи файла)
docker compose run --rm web python -m app.dump --unprocessed --mark-processed -o data/new.json
```

## Комментарии для LLM

Записи дневника лежат в таблице `comments`. Поле `processed_at` равно `NULL`, пока
запись не обработана. Будущая автоматизация может забирать записи так:

```sql
SELECT c.id, p.name, c.text, c.created_at
FROM comments c JOIN plants p ON p.id = c.plant_id
WHERE c.processed_at IS NULL;
```

После обработки нужно проставить `processed_at`. После правки записи на сайте `processed_at`
снова становится `NULL` — автоматизация увидит новый текст.

## Структура

```
app/main.py      — веб: маршруты
app/auth.py      — вход, CSRF
app/db.py        — схема SQLite и запросы
app/care.py      — расчёт сроков ухода (общий для сайта и напоминаний)
app/notifier.py  — рассылка в Telegram и обработка кнопок (отдельный контейнер)
app/telegram.py  — вызовы Telegram Bot API (без утечки токена в логи)
app/photos.py    — проверка и пережатие фото
app/backup.py    — резервные копии БД
app/seed.py      — начальный список растений
app/facts.py     — справочные факты по видам
app/diseases.py  — частые болезни и вредители по видам
app/repotting.py — рекомендации по пересадке по видам
app/catalog.py   — справочник видов для формы «Новое растение»
tests/           — тесты (pytest)
deploy.sh        — выкладка на сервер
```

## Тесты

Тесты работают с временной БД и тестовыми настройками — `.env` и `data/` не трогают.

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

## Безопасность

- Логин и пароль берутся только из окружения, сравниваются за постоянное время;
  при неверном пароле ответ задерживается на 1 с, после 5 неудачных попыток с одного IP
  вход блокируется на 15 минут.
- Сессия хранится в подписанной cookie (HttpOnly, SameSite=Lax; Secure — через
  `COOKIE_SECURE=true`). Все POST-запросы защищены CSRF-токеном.
- Фото: проверяются расширение и реальный формат (Pillow), лимит 10 МБ. Файл
  перекодируется в JPEG, поэтому EXIF с геолокацией удаляется.
- SQL только параметризованный. Токен бота в логи не попадает.
- Заголовки CSP, nosniff, запрет встраивания во frame.
- По умолчанию сайт слушает только 127.0.0.1; наружу — через `WEB_BIND=0.0.0.0`.
  При слабом пароле приложение пишет предупреждение в лог.
